# 1. Model/System Summary

ENDOLLM is a **multimodal, clinician-supervised artificial intelligence framework for endodontic diagnostic decision support**.

The current v65 implementation is not a single neural network.

It is an integrated system composed of:

```text
Frozen radiographic vision
+
External tooth-level visual models
+
Clinician-confirmed target-tooth selection
+
Structured clinical information
+
Deterministic diagnostic rules
+
Lesion-origin classification
+
Retrieval-augmented generation
+
Pretrained multimodal language model
+
Programmatic safety validation
+
Structured audit output
```

The current implementation is:

```text
Phase 4.5 Interactive Endodontic MLLM
v65
Stage 7.2
```

---

# 2. Intended Purpose

ENDOLLM is intended for **research into multimodal AI-assisted endodontic diagnostic reasoning**.

The system is designed to investigate whether radiographic information, structured clinical information, retrieved scientific evidence, deterministic clinical rules, and multimodal language-model reasoning can be integrated into an auditable clinician-supervised workflow.

The system is intended to support:

* research;
* algorithm development;
* diagnostic reasoning research;
* multimodal AI evaluation;
* clinician-supervised decision support;
* investigation of target-tooth grounding;
* investigation of fracture/lesion-origin reasoning;
* evidence-grounded clinical explanation.

---

# 3. Intended Users

The intended users are:

* dental researchers;
* endodontic researchers;

# 4. Clinical Use Boundary

ENDOLLM is a **research prototype**.

It is not intended to replace:

* clinical examination;
* pulp sensibility testing;
* electric pulp testing;
* percussion;
* palpation;
* periodontal probing;
* crack detection procedures;
* radiographic interpretation by a qualified clinician;
* CBCT when clinically indicated;
* specialist consultation;
* definitive clinical diagnosis.

The system explicitly retains a requirement for specialist verification.

# 6. Core Language Model

The multimodal language model used in v65 is:

```text
Qwen/Qwen2.5-VL-7B-Instruct
```

The model is loaded from the pretrained model repository.

The v65 implementation uses the model for inference.

It does not fine-tune the Qwen parameters during execution.

The model is loaded using 4-bit quantization with:

```text
NF4
Double quantization
Float16 computation
Automatic device mapping
```

The model is placed in evaluation mode.

---

# 7. Role of the Language Model

The LLM has a deliberately constrained role.

It is used for:

### Clinical history elicitation

Generating a limited number of focused questions.

### Clinical-language interpretation

Helping transform clinician-entered narrative into structured information.

### Evidence synthesis

Integrating retrieved literature with the established clinical context.

### Diagnostic explanation

Producing a structured, clinician-readable reasoning narrative.

The LLM is **not the primary diagnostic decision maker**.

The v65 prompt explicitly instructs the model not to override programmatic diagnostic labels, deterministic triage, red flags, or escalation information.

# 12. Target-Tooth Grounding

Target-tooth grounding is a central safety feature.

The system does not assume that every radiographic abnormality belongs to the symptomatic tooth.

Instead:

```text
Radiographic findings
        ↓
Tooth-level findings
        ↓
Clinician identifies symptomatic tooth
        ↓
System validates tooth
        ↓
Clinician confirms
        ↓
Target-specific evidence
```

This mechanism is designed to reduce inappropriate attribution of unrelated radiographic findings to the symptomatic tooth.

The v65 source explicitly instructs the reasoning model not to infer the symptomatic tooth from unrelated OPG findings.

# 14. Deterministic Clinical Rules


---

# 15. Stage 7.2 Lesion-Origin Classification

The current hierarchy is:

```text
Priority 1 — VRF suspected
Priority 2 — Cracked tooth suspected
Priority 3 — Standard endodontic origin supported
Priority 4 — Non-endodontic red flag
Priority 5 — Indeterminate
```

The corresponding categories are:

```text
VRF_SUSPECTED
CRACKED_TOOTH_SUSPECTED
ENDODONTIC_ORIGIN_SUPPORTED
NON_ENDODONTIC_RED_FLAG
INDETERMINATE
```

The hierarchy is applied programmatically before final LLM reasoning.

---

# 16. Vertical Root Fracture Pathway

The Stage 7.2 VRF gate requires:

```text
previously treated
AND
(
    isolated narrow deep pocket
    OR
    coronal/lateral sinus tract
    OR
    J-shaped / halo morphology
)
```

If satisfied, the system classifies the lesion origin as:

```text
VRF_SUSPECTED
```

with priority:

```text
1
```

---

# 17. Cracked-Tooth Pathway

The cracked-tooth gate requires:

```text
(
    pain on release
    AND
    difficulty localizing pain
)
OR
visible crack line
```

If satisfied:

```text
CRACKED_TOOTH_SUSPECTED
```

with priority:

```text
2
```

The v65 source explicitly prevents pain on release alone from automatically establishing crack suspicion.

---

# 18. Standard Endodontic-Origin Pathway

The standard endodontic-origin gate requires:

```text
cold response = False
AND
EPT response = False
```

and is evaluated after the higher-priority fracture pathways.

The resulting category is:

```text
ENDODONTIC_ORIGIN_SUPPORTED
```

---

# 19. Non-Endodontic Red Flag

The non-endodontic red-flag pathway is activated when:

```text
(
    cold response = True
    OR
    EPT response = True
)
AND
periapical lesion present
```

The category is:

```text
NON_ENDODONTIC_RED_FLAG
```

The system deliberately does not invent rare non-endodontic entity names when evidence is insufficient.

The LLM is instructed to refer to such situations generically as non-endodontic or fibro-osseous patterns when appropriate.

---

# 20. Indeterminate Classification

If none of the preceding gates are satisfied:

```text
INDETERMINATE
```

The system preserves uncertainty rather than forcing a definitive classification.

This is an intentional component of the safety architecture.

---

# 21. LLM Safety Constraints

The LLM receives several explicit constraints.

It is instructed to:

* preserve the target-tooth lock;
* preserve verified clinical findings;
* respect the Stage 7.2 classification;
* respect programmatic triage;
* respect escalation;
* use retrieved literature only as supporting evidence;
* avoid unsupported rare diagnoses;
* avoid converting a radiographic lesion into a symptomatic diagnosis by itself.

These constraints are part of the model's runtime architecture rather than properties of the underlying pretrained Qwen model.

---

# 22. Post-Generation Safety Validation

After LLM generation, v65 runs a programmatic validation step.

The validator specifically checks for inappropriate claims concerning:

### Pulp vitality

For example:

```text
confirms pulp vitality
indicates pulp vitality
demonstrates pulp vitality
proves pulp vitality
confirms a vital pulp
indicates a vital pulp
```

when a positive cold response is present.

### PAI interpretation

The validator also checks for inappropriate statements treating PAI as a direct clinical probability or diagnosis.

This creates a separate safety layer after LLM generation.

# 25. Known Limitations

## 25.1 Research prototype

ENDOLLM v65 is a research implementation and is not a validated autonomous clinical diagnostic system.

## 25.2 Upstream model dependence

Performance depends on the underlying frozen visual models and external OPGAgent models.

## 25.3 Clinical-input dependence

The quality of the output depends on the completeness and accuracy of clinician-provided clinical information.

## 25.4 Target-tooth dependence

The target-tooth workflow requires appropriate clinician identification and confirmation.

## 25.5 Retrieval dependence

Evidence quality depends on the underlying knowledge base and retrieval index.

## 25.6 LLM limitations

Qwen2.5-VL may produce incorrect or incomplete reasoning. Programmatic safeguards reduce but do not eliminate this possibility.

## 25.7 Rule-based limitations

The Stage 7.2 hierarchy represents explicitly programmed logic and requires independent clinical validation.

## 25.8 Dataset limitations

Performance should not automatically be generalized beyond the populations, imaging conditions, datasets, and clinical scenarios represented in the evaluation data.

# 26. Bias and Generalization

Potential sources of bias include:

* dataset composition;
* radiographic acquisition conditions;
* annotation practices;
* institution-specific characteristics;
* prevalence of different lesion types;
* clinical documentation differences;
* model-specific biases;

# 27. Safety Considerations

ENDOLLM incorporates multiple safety mechanisms:

```text
1. Clinician target-tooth confirmation
2. Structured clinical representation
3. Deterministic diagnostic rules
4. Stage 7.2 precedence hierarchy
5. Authoritative triage
6. Escalation logic
7. LLM prompt constraints
8. Post-generation validation
9. Specialist verification requirement
```

These mechanisms are intended to constrain inappropriate LLM behavior.

They do not constitute independent clinical validation.

# 28. Human Oversight

The system requires clinician participation.

* interpreting the system output;
* determining whether additional examination or imaging is required;
* making the final clinical decision.

ENDOLLM should therefore be regarded as a **clinician-supervised decision-support system**.

# 39. Summary

ENDOLLM v65 is a hybrid multimodal clinical AI framework in which:

```text
Visual models
      ↓
Target-tooth grounding
      ↓
Clinical information
      ↓
Deterministic diagnostic rules
      ↓
Lesion-origin classification
      ↓
Triage and escalation
      ↓
Evidence retrieval
      ↓
Qwen2.5-VL reasoning
      ↓
Safety validation
      ↓
Structured audit output
```

The system is designed so that the language model provides **clinical questioning, evidence synthesis, and explanation**, while deterministic programmatic components establish the authoritative diagnostic and safety state.

ENDOLLM is intended for research and clinician-supervised decision support and should not be interpreted as an autonomous clinical diagnostic system.
